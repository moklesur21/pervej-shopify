# T0.1 — Environment Setup
**Module 0 · Tutorial 1 of 26 · Est. 2–3 hours (much of it waiting on installs)**

**Goal:** By the end of this tutorial you have a free Shopify sandbox, the CLI running, Dawn scaffolded locally with hot reload working, and your first theme pushed to a store — the exact loop we'll use on every future client job.

**Prerequisites:** a computer you can install software on · a GitHub account · an email address for the Partner signup. **Total cost: $0.** Nothing in this series requires a paid plan.

---

## 1. Concept

Shopify is a **hosted platform**. There is no local Shopify — you never install it, never touch its servers, never see its database. The development loop looks like this:

```
theme files on your machine
        ↕  (Shopify CLI syncs)
development store in Shopify's cloud
        ↕
local preview URL with hot reload
```

Four pieces make it work:

- **Partner account** — free; lets you create unlimited development stores.
- **Development store** — a free, full-featured sandbox store. Can't take real payments (test orders only), storefront is password-protected by default. This is your playground now and your staging pattern later.
- **Shopify CLI** — the bridge: serve locally, push, pull, lint. Your WP-CLI equivalent.
- **Theme Check** — the Liquid/theme linter, built into the CLI. Your PHPCS equivalent.

---

## 2. Woo bridge

| You know (WooCommerce) | Here (Shopify) | Where the mapping breaks |
|---|---|---|
| LocalWP / wp-env — a full local site | Development store in the cloud + CLI sync | **There is no local Shopify.** The store always lives on Shopify's servers. |
| wp-admin on localhost | Store admin at `your-store.myshopify.com/admin` | Admin is hosted; you can't extend it with PHP |
| `wp-content/themes/child-theme/` | A theme folder anywhere on disk; CLI pushes/pulls it | No parent/child themes — you edit a full copy of the theme |
| WP-CLI | Shopify CLI | — |
| PHPCS + WPCS | `shopify theme check` | — |
| `debug.log`, `error_log()`, Query Monitor | CLI terminal output + browser devtools + Liquid's `| json` filter (T1.1) | **No PHP, no server logs, no Xdebug** |
| Staging = a second WP install | An **unpublished theme** on the same store | Store data (products, orders) is shared; only the theme layer is separate |
| FTP / SSH into the server | Doesn't exist | The CLI and the admin are the only doors |

> **The restriction that stings first** — no database access, no server, no production file system — is the same reason there's no server maintenance, no caching-plugin roulette, and no PHP-version hell. It feels like handcuffs for about a week. Then it feels like a weight removed.

## 3. Setup — step by step

### Step 1 — Create a Shopify Partner account (free)

1. Go to **partners.shopify.com** and sign up (business name can just be your name).
2. This account is the umbrella for every dev store you'll ever create.

### Step 2 — Create a development store

1. Partner Dashboard → **Stores → Add store → Create development store**.
2. Purpose: choose the **test/build** option (exact wording shifts occasionally).
3. Name it `yourname-training` — this one is your permanent playground.
4. If offered a data option, choose **test data** — sample products save you an hour of typing.

Dev stores are free forever. You can create as many as you want — later, one per practice project.

### Step 3 — Install Node.js

```bash
node -v
```

You need the current LTS (**v22+**; Shopify's docs currently list 22.12 or higher). If missing or old, install the LTS from **nodejs.org**, then reopen your terminal and check again.

### Step 4 — Install Shopify CLI

```bash
npm install -g @shopify/cli@latest
shopify version
```

Use npm on macOS too. The Homebrew formula (`brew tap shopify/shopify && brew install shopify-cli`) builds its dependencies from source on macOS 14 and can hang. If an old Homebrew copy is installed, run `brew uninstall shopify-cli` before the npm install.

Notes worth knowing:
- Current CLI is **4.x** and **updates itself** automatically through the package manager you installed it with.
- Old tutorials tell you to also install `@shopify/theme` or Ruby — **outdated**, ignore them. One package is all you need now.
- Windows: if `shopify` isn't found after install, open a **new** terminal window first (PATH refresh).

### Step 5 — Verify Git

```bash
git --version
```

Install from **git-scm.com** if missing. House rule from day one: every theme lives in a **private GitHub repo**.

### Step 6 — Scaffold Dawn locally

**Why Dawn, not Horizon?** Horizon is Shopify's newer default for merchants, but Dawn's simpler architecture is the right learning base — everything you learn transfers, and T1.6 covers Horizon properly.

```bash
shopify theme init dawn-playground
```

- If the CLI asks which theme to clone, pick **Dawn**. (To force it: add `--clone-url https://github.com/Shopify/dawn`.)
- `cd dawn-playground` and look around: `assets/ config/ layout/ locales/ sections/ snippets/ templates/`. Don't study them yet — that's T1.2's whole job.

### Step 7 — Start the dev server (the moment it clicks)

```bash
shopify theme dev --store your-store.myshopify.com
```

1. First run opens a browser window → log in with your Partner account and authorize.
2. The CLI prints a few URLs — open the local one: **http://127.0.0.1:9292**.
3. That's Dawn, running from **your local files**, against **your dev store's data**.

**Prove the hot reload.** Open `layout/theme.liquid`, and just after the `<body ...>` tag add:

```html
<p style="background:red;color:#fff;text-align:center;margin:0;">HOT RELOAD WORKS</p>
```

Save → watch the browser update within a second or two → delete the line → save again.

Two safety facts to internalize:
- `theme dev` serves your files on a private **development theme**. The store's published theme — what a visitor would see — is untouched. Safe by design.
- **Ctrl+C** stops the server. Stop it and restart it once now, just so you've done it.

### Step 8 — Run Theme Check

```bash
shopify theme check
```

Dawn should come back clean or nearly so. Remember this command — it runs before **every** delivery in our QA checklist, same as PHPCS did in your Woo work.

### Step 9 — Put it in Git

```bash
git init
git add .
git commit -m "Dawn baseline (untouched)"
```

(If the scaffold left a `.git` folder behind, delete it first — `rm -rf .git` — so your history starts clean.)

Create a **private** GitHub repo, add it as remote, push. The "untouched baseline" first commit is a permanent habit: on client work, it means every diff shows exactly what *we* changed.

### Step 10 — Push the theme to the store

```bash
shopify theme push --unpublished
```

Give it a name when prompted (e.g., `T0.1 practice`). Then in the dev store admin: **Online Store → Themes** → your theme is in the library → click **Preview**.

You've now used both halves of the loop:
- **`theme dev`** = live-sync preview from your machine (nothing stored on Shopify)
- **`theme push`** = upload a copy into the store's theme library

### Step 11 — Meet the rest of the core commands (2 minutes)

```bash
shopify theme list      # themes on the store, with IDs
shopify theme pull      # download a theme — this is how client work will start
shopify theme --help    # the full menu
```

## 4. Claude Code drill

Light one today — the full Shopify configuration for Claude Code (`@shopify/dev-mcp`, project `CLAUDE.md`, prompting patterns) is T0.3. Today builds two habits:

**Drill A — Explore with AI.** Open Claude Code inside `dawn-playground` and ask:

> "Walk me through this Shopify theme's folder structure. I'm a senior WooCommerce developer — for each directory, tell me the closest WordPress/Woo equivalent and where that comparison breaks down."

Read the answer with the actual folders open beside it, and **verify at least one claim yourself** by checking the files.

**Drill B — Troubleshoot with exact errors.** If anything in Section 3 failed, paste the **complete error output** — not a paraphrase — into Claude Code and let it diagnose. Exact errors in, better fixes out.

**The rule that starts today and never ends:** AI output isn't done until you've read it and checked it against reality. *The review is the skill.*

## Troubleshooting quick hits

- **`shopify: command not found`** → open a new terminal first; then check npm's global bin is on your PATH (`npm config get prefix`).
- **Login loop / auth weirdness** → `shopify auth logout`, then rerun `theme dev`.
- **Store flag format** → the full `your-store.myshopify.com` always works (the bare store handle usually does too).
- **CLI install complains about Node** → upgrade Node to current LTS, then reinstall the CLI.
- **Windows** → prefer PowerShell or Git Bash; install as a regular user so npm globals land on your PATH.
- **Auth hangs on restrictive networks** → try another network once to rule out a proxy/firewall issue.
