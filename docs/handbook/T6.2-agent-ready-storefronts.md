# T6.2 — Agent-Ready Storefronts
**Module 6 · Tutorial 23 of 26 · Est. 4–5 hours**

**Goal:** Take the dev store from "whatever Shopify generates by default" to a **verified** agent-ready state — and come out the other side with the reusable **S6 delivery checklist**, which is the thing we actually sell. You'll audit the store the way an AI agent reads it, fix the product data that agents rank on, do the small amount of theme work that's genuinely ours, and then prove the result by querying the store through its own UCP endpoint.

**Prerequisites:** T1.5 (metafields/metaobjects — half of this tutorial is metafield work), T5.1 (attribution habits), T5.2 (you'll read JSON-RPC responses without flinching), T6.1 (same dev store; leave the B2B setup in place — agent-readiness is orthogonal and must not break it). The Shopify AI Toolkit plugin from T0.3 must be installed; it ships the `ucp` skill you'll use in Drill D.

**Service S6 — the differentiation wedge.** Almost no agency has this on the menu yet. Read Section 1.4 twice: the scoping conversation is where this service is won or lost.

## 1. Concept

### 1.1 What "agent-ready" means in September 2026

AI shopping surfaces (ChatGPT, Microsoft Copilot, Google AI Mode / Gemini, Perplexity, the Shop app) reach a Shopify store through **three distinct layers**. Keep them separate in your head — each has a different owner.

| Layer | What it is | Who owns it |
|---|---|---|
| **1. Syndication — Shopify Catalog + Agentic Storefronts** | Shopify structures the store's product data (category, attributes, variant consolidation, identical-item grouping) and pushes it to the AI channels in real time, with live price and stock. Orders come back into the admin with AI-channel attribution. Enabled by default for eligible stores; managed from **Sales channels › Agentic** (its own admin page since May 2026: per-channel toggles, performance across AI channels, the queries the store ranks for, and data-quality recommendations). | **Merchant** flips switches and accepts terms. **We** fix the data it reads. **Shopify** does the syndication. |
| **2. Protocol — UCP (Universal Commerce Protocol)** | The open standard (Shopify co-developed it with Google; Amazon, Meta, Microsoft, Salesforce, Stripe, Etsy, Target, Wayfair back it) for how agents discover, cart, check out, and track orders. Every Shopify store is UCP-enabled: discovery at `/.well-known/ucp`, an MCP endpoint at `/api/ucp/mcp` exposing `search_catalog`, `lookup_catalog`, `get_product`, plus Cart, Checkout and Order MCP servers behind it. ChatGPT's own checkout protocol is bridged by Shopify as well. | **Shopify.** We *consume* it to verify — we never implement it. |
| **3. Open web — the theme** | What crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, …) read directly: `/agents.md` (canonical; `/llms.txt` and `/llms-full.txt` mirror it), `robots.txt`, JSON-LD structured data in the rendered HTML, `/products/{handle}.json`, the sitemap, the policy pages. Separate from Catalog syndication; both matter. | **Us.** Theme code, reviewed like any other delivery. |

The first thing to internalize: **the work is product data, not code.** Roughly 80% of an S6 engagement is data readiness, 15% is theme structured data and discovery files, 5% is verification. The code is small; the *judgment* — what's missing, what's wrong, what will make an agent skip the product — is the service.

### 1.2 What makes an agent skip a product

When a Catalog-powered search or a crawler evaluates a product, these are the failure modes — memorize them, they are your audit:

1. **No Standard Product Taxonomy category** → no category metafields → no structured attributes → the product ranks on title text alone.
2. **Attributes buried in prose or in metaobjects Catalog doesn't read.** "100% linen, 240 gsm" inside a paragraph is invisible; as a metafield it's a filter.
3. **Variants split into separate products** without Combined Listings → the agent sees five near-duplicates instead of one product with five colors.
4. **Missing barcode/GTIN, vendor, product type** → the product can't be matched or de-duplicated against the wider catalog.
5. **Thin or marketing-only descriptions** → nothing factual for the agent to quote; "elevate your everyday" is not an answer to "is it machine-washable?"
6. **Missing image alt text** → media that can't be described.
7. **Unpublished policies** → no shipping/returns links in the agent response → the agent hedges, the shopper moves on.
8. **Crawlers blocked** (robots rules, password page) → the open-web layer is dark even if Catalog is fine.
9. **Stale price or stock on the web** — Catalog is live-synced, but any scraped surface shows what the page said last time it was crawled. Structured data with correct availability limits the damage.

Notice: nine reasons, and only one (8) is code-adjacent. That's the shape of the work.

### 1.3 The honesty ladder for S6

Same discipline as T5.2's Flow → Zapier → middleware ladder. Quote the lowest rung that solves it.

1. **Platform default** — Catalog + Agentic Storefronts + managed `agents.md` already cover most stores. Sometimes the honest answer is "your store is already in ChatGPT; here's what's holding it back."
2. **Data + theme readiness (S6, 2–5 days)** — audit, taxonomy and metafields, descriptions and alt text, policies, Knowledge Base, Catalog Mapping, JSON-LD, robots and agents.md, verification report. This is the service.
3. **Catalog Mapping configuration** — for stores with custom data conventions (tag prefixes, delimiters in titles, attributes in metaobjects). Part of S6 when needed.
4. **A custom on-site shopping assistant** built on the Storefront Catalog MCP — that is an **app build** (S3/S4 pricing), not S6. Don't let "AI-ready" quietly grow into "build us an AI."

**Never quote an app or a custom agent for what the platform does by default.** An agency that catches you doing that is an agency you've lost.

### 1.4 Scoping: who does what

| Merchant / agency does | We do | Shopify does |
|---|---|---|
| Accepts Agentic Storefronts terms; decides which AI channels are on | Readiness audit with before/after evidence | Catalog structuring and syndication |
| Approves Knowledge Base content (FAQs, brand voice, policy summaries) | Taxonomy categories, metafield definitions, bulk data mutations | UCP discovery + MCP endpoints |
| Owns the robots decision (allowing AI crawlers is a business choice, not ours) | Descriptions, alt text, barcodes, vendor, product type (or a data spec the merchant fills) | Checkout inside the AI surface; order attribution |
| Supplies review data if any (never invented) | Theme JSON-LD, `robots.txt.liquid`, `agents.md.liquid` when warranted | Managed `agents.md` default |
| | Catalog Mapping + Combined Listings review | |
| | Verification via the UCP endpoint; report; Loom | |

Eligibility for the syndication layer varies by plan, market and Shopify Payments availability, and the channel list changes every few months. **Check the client's own Agentic page** before promising a channel — never promise from memory.

### 1.5 Woo bridge

| Woo | Shopify | Where it breaks |
|---|---|---|
| Product JSON-LD comes from Woo core (`WC_Structured_Data`) and SEO plugins; updates itself | JSON-LD is **theme code** — Dawn emits Product (per-variant offers) and Article schema from its main sections; whatever the theme says is what agents get | It's in *your* review scope now. A section edit can silently break a store's structured data, and no plugin will fix it behind you |
| Google feed plugins + Merchant Center; you build and debug feeds | **Shopify Catalog** syndicates automatically; Catalog Mapping adjusts sources | You don't build feeds anymore — you fix data at the source and configure mapping |
| `robots.txt` is a real file, or the `robots_txt` filter | `templates/robots.txt.liquid` | Same idea; the default is Shopify's, not yours |
| `llms.txt` = a static file at web root or a plugin | `templates/agents.md.liquid` overrides a **managed default** that already exists on every store | Restricted Liquid context: only `request` and the `agents` object. `shop`, `collections`, `pages` render **blank**. Every Woo instinct about "just loop the categories" fails here |
| Machine-readable products = the public Store API (`/wp-json/wc/store/v1/products`) | `/products/{handle}.json`, `/products.json`, Storefront API, **and** the UCP MCP endpoint | UCP is a *standard* with an agent-profile requirement and versioned capabilities; Store API is just open JSON |
| Agent checkout: nothing native | UCP Cart/Checkout MCP; checkout happens inside ChatGPT/Copilot with the merchant's own rules and discounts | Zero build on our side — and zero ability to customize it beyond what checkout already allows |
| Attribution: UTM + referrer + GA4 | Orders carry AI-channel attribution natively; Agentic page shows sessions, orders, conversion by channel | GA4 (T5.1) still matters for agent-referred *web* sessions; the two views don't reconcile perfectly — say so in reports |
| Getting a Woo store into AI channels | Shopify's **Agentic Plan** lets non-Shopify merchants list in Shopify Catalog and sell through the same AI channels (no monthly fee; transaction fees; market eligibility varies) | The irony is the opportunity: a Woo client of the same agency can buy S6 through Shopify's infrastructure. Not in the W-series yet — flag it |

## 2. Claude Code drill

**Setup**
- Dev store from T6.1. Duplicate the theme, work on the copy, on a branch — house rule.
- Install the UCP CLI: `npm install -g @shopify/ucp-cli` (Node 18+). The AI Toolkit plugin from T0.3 gives Claude Code the `ucp` skill that drives it.
- Create `docs/agent-readiness-audit.md` — you'll fill it through the drills — and `docs/s6-agent-readiness-checklist.md` (empty for now; it's the last thing you write).

**Expect gating on a dev store.** Development stores are password-protected, may not be eligible for Catalog syndication, and may not show the Agentic channel page. That's fine: the *data and theme work* is identical on any store, and every gated check becomes a line in the client checklist ("verify on live store after deploy"). Record each gate you hit; don't fight it.

### Drill A — Audit the store the way an agent reads it *(read-only, no AI yet)*

Hand-write the findings. The point is calibrating your own eye before Claude Code offers opinions.

1. **Discovery files.** `curl -s` each of `/agents.md`, `/llms.txt`, `/llms-full.txt`, `/.well-known/ucp`, `/robots.txt`, `/sitemap.xml`. Save the raw output into the audit. Note what the managed `agents.md` contains (endpoints, browse URLs, policies) and what's missing or generic. Confirm `/llms.txt` mirrors `/agents.md` — that's the fallback chain in action.
2. **Raw product shape.** `curl -s /products/{handle}.json` for three products. Save these — they're your **before** snapshots.
3. **Theme structured data.** `grep -rn "application/ld+json" layout sections snippets`. List every schema type the theme emits (Product, Article, Organization, BreadcrumbList, WebSite) and which fields each carries. Render one product page, copy the HTML, and run it through Google's Rich Results Test or the schema.org validator in code-snippet mode (a URL test can't get past the dev-store password).
4. **Product data audit** for the same three products: taxonomy category assigned? category metafields populated? barcode, vendor, product type? alt text on every image? description factual (materials, dimensions, what's included, care, compatibility)? weight? Combined Listings where variants are split? Policies published (shipping, refund, privacy, terms)?
5. **Admin.** Open **Sales channels › Agentic** if it exists on the dev store. Screenshot: channels and their state, terms status, the Sources / Catalog Mapping section, recommendations. If it's absent, write "gated on dev store" and move on.

Then, and only then: paste the audit into Claude Code and ask *"What did I miss, as an AI shopping agent evaluating this store?"* Pick one correction and verify it against shopify.dev before accepting it.

### Drill B — Fix the data at source *(the billable part)*

Work on the three products from Drill A.

1. **Taxonomy.** Assign a Standard Product Taxonomy category to each product in the admin. Accept the suggested **category metafields** and fill them — these are the attributes Catalog reads first.
2. **Hand-written data spec.** Before any prompt, write `docs/metafield-spec.md`: which custom attributes matter for this niche (material, compatibility, certifications, use case…), namespace and key, type, and which products get which values. Set **storefront access** on each definition so the theme and Storefront API can read them.
3. **Mutations by Claude Code, reviewed by you.** Ask Claude Code to generate the Admin GraphQL for the spec — `productUpdate` for category, vendor and product type; `productVariantsBulkUpdate` for barcodes; `metafieldsSet` for attributes; media updates for alt text. Let the toolkit validate against the live schema. **Review protocol** on every mutation before it runs: right GIDs, right namespace/key/type, no unrelated fields overwritten, safe to re-run. Run them against the dev store. This is the same discipline as T5.2's middleware — an AI-drafted write to a client store is reviewed line by line or it doesn't run.
4. **Descriptions and alt text.** Rewrite the three descriptions as fact-rich merchant copy: what it is, what it's made of, dimensions, what's in the box, care, compatibility. Claude Code may draft; you edit for truth — nothing goes in that the merchant can't stand behind. Descriptive alt text on every image.
5. **Policies.** Fill all four in Settings › Policies. Unpublished policies are the most common, cheapest-to-fix gap you'll find on client stores.
6. **Knowledge Base.** Install Shopify's Knowledge Base app if the dev store allows it; add five FAQs and a returns summary in the brand's voice. If gated, document the step for the client checklist.
7. **Catalog Mapping.** If **Sales channels › Agentic › Sources** is available: review how title, description and category are sourced; map to your metafields where the defaults are wrong; check variant grouping (Combined Listings by default). If gated, document.

### Drill C — The theme layer *(small, and reviewed like anything else)*

1. **`robots.txt.liquid`.** Read the current `/robots.txt`. Are AI crawlers allowed? Only add the template if a change is actually needed — and note that this is the **merchant's** decision to make; your job is to surface it with the trade-off (blocking AI crawlers also affects Google-Extended and similar). Log the decision.
2. **Structured data.** Have Claude Code complete the Product JSON-LD: `sku`, `gtin` from barcode, `brand` from vendor, one `Offer` per variant with price, currency and availability, the image array. Add Organization JSON-LD to `theme.liquid` with `sameAs` from the theme's social settings, and BreadcrumbList on product and collection templates. **Review hunts:** invalid JSON when a Liquid value is empty (use the `json` filter, never string-concatenate), a *second* Product entity injected by an app (the validator will show two — one has to go), unescaped quotes, and `aggregateRating` — **emit it only from real review data; never invent it.**
3. **`templates/agents.md.liquid`.** Build one. Use the `agents` object for everything dynamic: `agents.store_name`, `agents.store_url`, `agents.ucp_discovery_url`, `agents.mcp_endpoint_url`, `agents.ucp_versions`, `agents.currency`, `agents.sitemap_url`. Hardcode what the restricted context can't give you: a one-paragraph description of what the store sells and who it's for, read-only browse URLs (`/collections/all`, `/products/{handle}.json`), policy URLs, any B2B or market notes. **No contact details** — the file is cached and served to every agent. Check all three URLs render it.
   Then **decide**: ship it, or delete it and keep the managed default? Shopify's own guidance is that the managed file is right for most stores and a custom one is yours to keep current forever. Write the decision and the reason in the audit. Knowing when *not* to ship the file you just built is the professional move.
4. Theme Check clean. Diff reviewed on the branch. Full purchase flow re-run — T6.1's wholesale scenario must still work exactly as before.

### Drill D — Prove it like an agent *(verification)*

1. **Tool discovery.** POST to `https://{store}/api/ucp/mcp`:
   ```json
   {"jsonrpc":"2.0","method":"tools/list","id":1,
    "params":{"arguments":{"meta":{"ucp-agent":{"profile":
    "https://shopify.dev/ucp/agent-profiles/examples/2026-08-25/valid-with-capabilities.json"}}}}}
   ```
   Every request needs a `meta.ucp-agent.profile` URL; the example profile from shopify.dev is fine for read-only verification. Expect `search_catalog`, `lookup_catalog`, `get_product`.
2. **Search.** `ucp catalog search --business https://{store} --set /query='<a term from your niche>' --view :compact --format md` (or ask Claude Code in plain language — the `ucp` skill picks the command). Does your enriched product come back? Open the full response: `categories` (google, shopify, merchant taxonomies), `metadata` (your metafields), `variants[].availability`, `seller.links` (your policies), `rating` (only if real). Paste it next to the Drill A "before" JSON.
3. **Product detail.** `ucp catalog get_product gid://shopify/Product/{id} --business https://{store} --set '/selected/0={"name":"<option>","label":"<value>"}'` — read the per-option `available` / `exists` signals. This is what an agent uses to answer "do you have it in blue, size 10?"
4. Re-fetch `/agents.md`; re-validate the JSON-LD on a rendered product page.
5. **If the password wall intercepts the endpoint:** record the gate, run steps 1–3 read-only against any live public Shopify store to learn the response shapes, and add "final UCP verification on live store after deploy" to the checklist. Read-only calls against a live store are safe and are exactly how you'll verify client work.
6. Write `docs/agent-readiness-report.md`: findings → fixes → before/after evidence (JSON snippets, validator screenshots, Agentic page screenshots where available) → open items that are merchant-side. This is S6's deliverable format.

**Finally,** write `docs/s6-agent-readiness-checklist.md` from everything above: the audit items, the merchant/dev/Shopify split, the proofs. Add `notes/agentic-layer-map.md` (the three-layer table from 1.1 with where each protocol and file lives) to the handbook folder.

- [ ] Custom metafield definitions match the hand-written spec; storefront access enabled
- [ ] Every AI-generated mutation reviewed (GIDs, namespace/key/type, no collateral overwrites, re-runnable) before execution
- [ ] All four policies published
- [ ] Knowledge Base populated — or documented as gated with the client step written out
- [ ] Catalog Mapping and variant grouping reviewed — or documented as gated

- [ ] Theme Check clean; branch only; diff reviewed

## 4. Done when

All boxes ticked **and** you can answer out loud, without looking:

1. The three layers of agent-readiness — which is ours, which is the merchant's, which is Shopify's? Name the file, page or endpoint that belongs to each.
2. An agent searched the store and your product didn't come back. Give five *data* reasons before you give a code reason.
3. The `agents.md` fallback chain, from memory — and why `shop.name` renders blank inside the template.
4. A client says "we want an AI shopping assistant on our site." Where does S6 end and a build begin, and how do you say it in a scoping call?
5. The same agency has a WooCommerce client who wants to be in ChatGPT. What's your answer? *(Agentic Plan, plus the open-web basics — and a note that our W-series doesn't cover this yet.)*
6. Why is `aggregateRating` the one JSON-LD field that gets a hard "never without real data" rule?
7. What's the honesty ladder for S6, and what's the sentence you say when a store is already fine?
