## 1. Concept — a rendering language, not a programming language

Liquid is the template language Shopify's servers use to turn store data into HTML. It is **deliberately limited**: no functions of your own, no database queries, no side effects. You work with the objects the current page gives you, transform them with filters, and control flow with tags. That's the whole language.

**The three building blocks:**

| Block | Syntax | Job | Example |
|---|---|---|---|
| **Objects** | `{{ }}` | Output data | `{{ product.title }}` |
| **Tags** | `{% %}` | Logic & flow | `{% if product.available %}` |
| **Filters** | `\|` inside `{{ }}` | Transform output, left to right | `{{ product.price \| money }}` |

**Context decides what exists.** A product template gets `product`; a collection template gets `collection`. A handful of globals exist everywhere: `shop`, `cart`, `customer`, `settings`, `request`, `collections`, `all_products`. Reference something that isn't in context and you get… nothing. Which brings us to the most important sentence in this tutorial:

> **Liquid fails silently.** A misspelled object or missing property renders as an empty string — no error, no warning, no log line. Your safety nets are Theme Check, the `| json` filter, and your own eyes.

### Core syntax reference

**Output & variables**

```liquid
{{ product.title }}
{{ product.title | escape }}                     {% # escape user-editable text %}
{% assign sale_count = 0 %}
{% capture badge %}Save {{ saved | money }}{% endcapture %}
```

**Control flow**

```liquid
{% if product.available %} In stock
{% elsif product.tags contains 'preorder' %} Preorder
{% else %} Sold out
{% endif %}

{% unless product.vendor == blank %} by {{ product.vendor }} {% endunless %}

{% case style %}
  {% when 'card' %} ...
  {% when 'row' %}  ...
  {% else %}        ...
{% endcase %}
```

Operators: `==  !=  >  <  >=  <=  and  or  contains` — no parentheses, conditions evaluate **right to left**. Keep them simple; split complex logic into `assign` steps.

**Loops**

```liquid
{% for product in collection.products limit: 6 %}
  {{ forloop.index }}. {{ product.title }}   {% # index is 1-based; index0 exists %}
  {% if forloop.first %}★{% endif %}
{% else %}
  <p>Nothing to show.</p>                    {% # for-loops have an else: the empty state %}
{% endfor %}
```

Also available: `offset`, `reversed`, `{% break %}`, `{% continue %}`, `forloop.last`, `forloop.length`.

**Snippets**

```liquid
{% render 'product-spotlight', product: product, style: 'card' %}
```

`render` is **scope-isolated**: the snippet sees only what you pass it — nothing else, not even the caller's `forloop`. (The old `{% include %}` shared scope; it's deprecated — if AI output ever suggests it, that's a review flag.)

**The `{% liquid %}` tag** — multiline Liquid without delimiter noise. Dawn uses it everywhere, so read it fluently:

```liquid
{% liquid
  assign on_sale = false
  if product.compare_at_price > product.price
    assign on_sale = true
  endif
  echo product.title
%}
```

**Comments & whitespace**

```liquid
{% # single-line comment %}
{% comment %} block comment {% endcomment %}
{%- if true -%}   {% # hyphens strip surrounding whitespace from output %}
```

### Filters starter pack

| Filter | Does | Example |
|---|---|---|
| `money`, `money_with_currency` | Format subunit prices | `{{ 1999 \| money }}` → $19.99 |
| `escape` | HTML-escape (your `esc_html`) | `{{ product.title \| escape }}` |
| `default` | Fallback value | `{{ product.vendor \| default: shop.name }}` |
| `t` | Translation — pulls from `locales/` (how the no-hardcoded-strings rule is implemented) | `{{ 'products.product.sold_out' \| t }}` |
| `image_url` + `image_tag` | Sized CDN URL → responsive `<img>` | `{{ product.featured_image \| image_url: width: 400 \| image_tag }}` |
| `json` | **Your `var_dump`** | `<pre>{{ product \| json }}</pre>` |
| `truncate`, `upcase`, `downcase`, `append`, `prepend`, `replace`, `split` | String work | `{{ title \| truncate: 40 }}` |
| `size`, `first`, `last`, `where`, `map`, `sort`, `join` | Array work | `{{ products \| where: 'available' \| size }}` |
| `plus`, `minus`, `times`, `divided_by`, `modulo`, `round` | **All math** | `{{ price \| times: 2 }}` |
| `date` | Format dates | `{{ order.created_at \| date: '%b %d, %Y' }}` |

## 2. Woo bridge

| You know (Woo/PHP) | Here (Liquid) | Where the mapping breaks |
|---|---|---|
| `<?php echo esc_html( $product->get_name() ); ?>` | `{{ product.title \| escape }}` | No PHP context — escaping is a filter you apply, not a function you call |
| The Loop: `while ( have_posts() ) : the_post();` | `{% for product in collection.products %}` | No global state machine, no `setup_postdata` — iteration is explicit and local |
| `WP_Query` — query anything, anywhere | **You can't.** You get the context's objects plus limited globals (`collections['sale'].products`, `all_products['handle']` — capped per page) | The biggest break in Module 1. "Custom queries" become section settings + dynamic sources (T1.3) or metafields (T1.5) |
| `get_post_meta()` | `product.metafields.namespace.key` | Typed, definition-backed — T1.5 |
| `get_template_part()` — shares globals | `{% render %}` — isolated scope | Closer to a pure function: pass everything explicitly |
| `apply_filters()` — an extension point | Liquid filters — **transforms only** | Same word, unrelated concept. Nothing "hooks into" a Liquid filter |
| `var_dump()`, `print_r()` | `{{ object \| json }}` | Renders into the page — remove before commit |
| Prices as float dollars | Integer **subunits** (cents) | `product.price` → `1999`. Forget `\| money` once and ship "$1999" |
| PHP falsy: `0`, `""`, `[]`, `null`, `false` | **Only `nil` and `false` are falsy** | `""` and `0` are TRUE here — see gotcha #1 |

### The five gotchas that bite PHP developers

1. **Truthiness.** Only `nil` and `false` are falsy. An empty string passes `{% if product.description %}`. The idiom: `{% if product.description != blank %}` — `blank` catches nil, false, empty, and whitespace-only strings.
2. **No inline math or concatenation.** `{{ a + b }}` is a syntax error. Math is filters (`| plus:`), string-building is `append`/`prepend`/`capture`.
3. **Prices are subunits.** Every money value is in cents. `| money` on output, always; mental math in cents when comparing.
4. **Silent failure.** Typos render as nothing. Suspect emptiness? `| json` the object, run `shopify theme check`, view source.
5. **"Filter" means transform here.** Retire the WP meaning or you'll misread every sentence of Shopify docs.

## 3. Setup — the lab bench (5 minutes, scaffolding only)

Sections are T1.2's topic — today you just need one to host your snippet. Create `sections/t1-1-lab.liquid`, paste, don't study:

```liquid
<div class="page-width" style="padding: 40px 0; display: grid; gap: 24px;">
  {% for product in collections.all.products limit: 3 %}
    {% render 'product-spotlight', product: product, style: section.settings.style %}
  {% else %}
    <p>No products found — add a few to your dev store first.</p>
  {% endfor %}
</div>

{% schema %}
{
  "name": "T1.1 Lab",
  "settings": [
    {
      "type": "select",
      "id": "style",
      "label": "Render style",
      "options": [
        { "value": "card", "label": "Card" },
        { "value": "row", "label": "Row" },
        { "value": "debug", "label": "Debug" }
      ],
      "default": "card"
    }
  ],
  "presets": [{ "name": "T1.1 Lab" }]
}
{% endschema %}
```

Add it to the homepage via the theme editor (you did this in T0.2, Stop 7). The style dropdown in the editor will drive your snippet — a small preview of why sections matter.

## 4. Claude Code drill — one snippet, three render styles

Build `snippets/product-spotlight.liquid`: it receives `product` and `style`, and renders one of three layouts via `{% case style %}`.

### Part A — hand-write the first style. No AI.

You review AI Liquid for a living now; you can only review what you can write. Using just the reference above, write the **card** style:

- Featured image: `image_url: width: 300` piped to `image_tag`
- Title, escaped
- Price with `| money`; if `compare_at_price > price`, show it struck through **and** a "Save {amount}" line computed with `minus`
- Vendor line — only when vendor `!= blank`

Save, pick "Card" in the editor, verify in the preview. Fight the urge to peek at Dawn or ask Claude. Struggle is the point.

### Part B — AI writes the second style. You review.

Prompt Claude Code (note the patterns from T0.3):

> "In `snippets/product-spotlight.liquid`, add the `row` case: a compact horizontal layout — title (escaped, truncated to 40 chars), price with the money filter, and an availability badge: 'In stock' when `product.available`, otherwise 'Sold out'. Match the existing case structure, smallest possible diff, Theme Check clean. Explain any Liquid idiom that differs from PHP templating."

Run the **full T0.3 review protocol** on the diff. Then switch the editor dropdown to "Row" and verify.

### Part C — the debug style teaches the debug tool.

Add the `debug` case yourself — it's two lines:

```liquid
{% when 'debug' %}
  <pre style="font-size:11px; overflow:auto;">{{ product | json }}</pre>
```

Switch to "Debug" and **read the dump**. Find: `price` in cents · the `variants` array · `options_with_values` · what `featured_image` actually contains. This is the `WC_Product` getter map you didn't have to memorize — `| json` shows you any object's truth on demand.

### Part D — break it on purpose.

1. In the card style, change `product.title` to `produt.title`. Reload: the title *silently vanishes*. No error. Feel that.
2. Run `shopify theme check` — watch it flag the unknown object. Fix it.
3. Now make gotcha #1 real: add `{% if product.description %}has description{% endif %}`, clear the description on one dev-store product, and watch the text still print. Change the test to `!= blank` and watch it behave. Delete the experiment.

### Part E — read production Liquid.

Open Dawn's `snippets/price.liquid` — real-world Liquid: the `{% liquid %}` tag, assigns, money filters, `| t` translations. Ask Claude Code:

> "Explain `snippets/price.liquid` line by line. I know PHP templating; focus on the idioms that are new."

Verify one explanation yourself against the file. You'll meet this snippet again in every price-touching build.
